# 举报收件回执

举报的新建入口（`POST /api/reports`、`/post`、`/comment`、`/user`）在同一个数据库事务中保存举报和一条发给举报人的系统通知。事务提交后才发送 WebSocket / APNs / Aliyun 提醒。

- 类型：`report_received`；标题：`举报已收到`。
- 正文：`我们已收到你的举报，将尽快核查。你可以在「举报处理记录」中查看进展。`
- `sender_id` 为空；`related_type=report`，`related_id` 指向举报记录，不指向被举报用户或内容。
- 成功响应在既有 `report` 字段之外附带已提交的 `notification`。旧客户端可忽略新字段；新客户端可立即刷新通知列表，并用服务端通知 ID 去重。
- 重复举报返回原有举报记录，不创建或再次推送回执；同一举报人的并发提交用数据库行锁串行化。
- 举报或回执保存失败时一并回滚。推送渠道异常不影响已保存的举报和通知；关闭系统推送的用户仍能在应用通知中心查看回执。
- 锁屏只展示平台固定收件文案，不包含举报理由、目标内容、身份信息，也不通知被举报人。
- APNs 和前台通知都沿用 `notification:<id>` 去重键，以及现有推送/声音开关。

## 部署

必须将本次 `ios` 分支后端代码部署到实际运行的 API 服务，客户端更新本身不能让旧后端生成回执。此次没有新增数据库表或列；沿用现有发布与备份流程，不需为该功能新增迁移。APNs 是否可见仍取决于服务器已有配置和用户的系统通知授权。

客户端通知详情提供「查看举报处理记录」入口，只读取当前登录用户自己的举报记录。
