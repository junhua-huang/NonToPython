# 账号删除的只读核对

该工具辅助排查注销接口中的关联清理缺口，不执行注销，不将“账号不存在”解释为媒体、日志或备份已清理完成。

在后端服务器更新 `ios` 分支后，用后端相同的 Python 环境执行：

```sh
python scripts/account_privacy_inventory.py --env-file /www/wwwroot/NonToPyDev/NanTuPy/.env --account-id TEST_ACCOUNT_ID
```

运行前将 TEST_ACCOUNT_ID 替换为专用测试账号的数字ID。它只读取表结构和记录数量，不启动 `app.main`，不建表、迁移、发邮件、推送或删除数据。尽可能使用只读数据库权限。输出不含用户名、邮箱、消息正文、验证码、密钥、连接串或环境文件内容。

- `references`：真实数据库中指向该用户的外键及数量，含可空性和数据库级删除策略。
- `additionalRecords`：推送日志、验证码及登录尝试等可能没有用户外键的记录数量。
- `manualDecisions`：需要先确定共享社群、活动归属或运维记录处理方式的引用，不能机械连带删除其他用户的数据。
- `unverified`：COS对象版本和孤立媒体、数据库／云盘／快照备份、服务商日志及依法保留等仍需另外核对的范围。

检查不能代替删除功能修复、生产验收或备份恢复测试。当前注销接口仅调用 `db.delete(current)`；不要在尚未处理关联数据前承诺“注销即清空全部副本”。

可回传只读报告以便继续确定清理方案；不要发送 `.env`、数据库导出、证书、私钥或真实用户记录。
