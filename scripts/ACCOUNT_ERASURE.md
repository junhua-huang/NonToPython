# 注销清理实现与部署验收

此版本实现后端清理，代码与测试完成不等于已经在生产部署或完成云端备份核验。

## 数据库与账号

`DELETE /api/auth/account` 在同一事务中删除账号、资料、本人动态与评论、本人私信、关联点赞/浏览/搜索、好友与屏蔽、推送设备与令牌、通知投递、验证码、登录尝试、角色申请与资料、会话参与关系、实时补发和ACK记录。清除他人引用中的旧消息预览、自有帖子链接及指向已删评论的引用。动态删除同时清理该动态上的关联记录。

他人的独立动态、回复、私信和共享活动保留。原私信会话保留对方自有消息，离开的一方置空；原群主的社群归档、解除群主关联，其他成员内容保留。活动创建人解除关联，活动及其他人的评论保留。管理员审计保留动作与时间，删除注销操作人的身份、IP、备注等字段；部署历史保留，操作者解除关联。不能承诺删除其他人独立保存的副本或任意自由文本中的提及。

外键失败会整体回滚，不向云端执行删除。不关闭外键检查、不生成替代用户。新增未定义处理规则的用户外键会阻止注销。

成功后旧HTTP令牌失效；现有WebSocket重新收发时核对数据库状态并断开失效账号。跨进程发送也重新核对，不能只信内存连接。即使随后缓存清理失败，已提交的注销也不会返回误导性的500。

## 云端媒体和重试

事务写入 `account_erasures` 后，应用生命周期内的任务每5分钟处理队列。仅按 `avatars/covers/posts/comic/chat/general/{用户ID}/` 的完整目录前缀删除，避免把1号用户的目录匹配为10号。覆盖历史头像、未引用文件、对象历史版本、删除标记和未完成的分块上传。权限、对象锁、网络或配置问题会记录固定错误码并重试；不将第三方原始异常或密钥记入日志。

注销后先清扫一次；旧预签名上传链接最长1小时，至少65分钟后再次清扫验证，才可标记媒体完成。65分钟是再次检查的最早时间，不是所有故障情况下的完成承诺。

旧版没有用户目录的COS资源无法仅凭URL证明归属，记为 `legacy_review_required`，不自动删除他人资源。管理员可在下方受保护接口查看待核验对象键，核对所有权后在COS控制台删除对应对象的全部版本、标记和分块；不能把队列直接改成完成而不核验。历史本地上传目录也须单独核对。

## 定期清理

任务每5分钟按批次处理：验证码到期24小时后，登录尝试及推送日志30天后，实时补发7天后，ACK去重1天后。验证码的24小时窗口保留现有小时级限流依据；不会为清空验证码破坏限流。积压和故障需查看任务状态并处理。Nginx、进程输出、主机日志及供应商投递日志不由这些数据库任务覆盖。

## 迁移与部署

服务器项目目录为 `/www/wwwroot/NonToPyDev/NanTuPy`。在该项目当前使用的Python环境中更新 `NonToPython` 的 `ios` 分支、安装依赖后执行：

```sh
python -m alembic upgrade head
```

迁移头为 `2026_10_24_0100`。必须先完成迁移，再用宝塔当前项目管理方式重启后端；不要凭猜测停止其他服务。Docker部署原入口会先迁移再启动。此迁移不删除业务数据，将6个共享/历史记录的操作者字段改为可空并新建队列表。已产生注销账本后不能直接降级抹去证据；迁移会拒绝这种降级。

COS服务账号需具备对应桶的版本列表、分块上传列表，以及用户目录下的对象版本删除和分块终止权限。缺少权限不会伪装成功。不要为方便而公开桶或把服务端密钥交给客户端。

受管理员权限保护的状态接口：

- `GET /api/admin/privacy/status`：队列计数与清理规则。
- `GET /api/admin/privacy/erasures/{注销返回的erasure_id}`：单条状态。
- 上一接口追加 `?include_legacy_keys=true`：仅管理员按需查看旧对象键；不要把结果公开。

公开规则页与原生73.1内置文档同源：`/api/legal/privacy.html`、`/api/legal/terms.html`、`/api/legal/community.html`；该API前缀可复用现有反向代理。根目录旧URL也有兼容跳转，但若Nginx直接返回旧静态页面，须修改对应location后才会生效。`manifest.json`保留原有发布核验状态，不能把公开页面可访问当作全部合规已验收。

## 备份恢复防止账号复活

账本仅保存注销编号、原用户数字ID、处理时间和任务状态，不能存入邮箱、密码、聊天正文。账本本身有用途和访问限制；在实际云盘/数据库备份保留窗口未核清前，不自动丢弃恢复排除依据。`backup_status`保持 `unverified`，COS完成不会改变它。

定期把最少恢复排除清单导出到运营者保护的位置，独立于会回滚的数据库备份：

```sh
python scripts/export_erasure_ledger.py --env-file /www/wwwroot/NonToPyDev/NanTuPy/.env --output /受保护目录/本次独立备份名.json
```

路径必须替换为真实受控位置，脚本拒绝覆盖、以0600权限创建，只导出编号/ID/时间。不要放进公开目录或仓库。此命令不修改数据库；导出不等于已经配置独立备份。

恢复旧业务备份前关闭对外流量和推送，保留最新账本与独立排除清单。将最新账本合并进恢复环境后，鉴权会拒绝已注销ID；仍需在恢复环境重新执行这些账号的 `erase_account`、处理媒体重试并验收后，才能恢复流量。若只恢复旧数据库而丢失最新账本，软件无法知道后来发生的注销，不能据此声称删除有效。

阿里云数据库备份、云盘快照、宝塔备份、腾讯COS版本与跨区域复制均需按真实配置核对保留窗口、权限及轮换；代码不能推断当前配置，也不承诺“无备份”或固定天数内所有备份清空。

## 专用测试账号验收

上线前在专用账号验证注销前后数据、旧token、双进程WebSocket、推送设备、引用预览与补发内容、媒体当前及历史版本；等待旧上传链接过期后的最终清扫。模拟COS权限不足，确认业务库删除成功、媒体显示待重试；恢复权限后再完成。另用隔离恢复环境验证最新账本阻止旧账号复活。没有这些生产与恢复实测记录，不得将 `accountDeletionVerified` 或 `releaseReviewed` 改为true。
